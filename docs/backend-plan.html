목업(sessionStorage) → Vercel + Postgres 무료 운영 → 모임·모임원 관리 → (필요할 때) NestJS 분리

작성 2026-11-15 · 무료 한도 수치는 작성자 지식(2026-06) 기준 근사치 — 가입 전 각 공식 요금 페이지 재확인 필수

결론현재 상태파괴적 제안인프라 선택 아키텍처데이터 모델로드맵리스크·한도결정 필요

한 줄 결론

Vercel(Hobby) + Supabase(Free: Postgres + Auth) 로 가고, NestJS는 지금 만들지 않는다. 대신 서버 로직을 src/server/ 에 프레임워크 무관 순수 TS로 모아 두면 Nest 이전이 "복사 + 데코레이터 추가"로 끝난다.

  1. 지금 당장: 현 목업 그대로 Vercel에 배포 (0.5일, 코드 변경 없음)
  2. 1차(1인 사용, 로그인 없음) = 2가지: ① DB·백엔드 연동(로컬 Supabase, 진도·지문 저장) ② AI로 지문·문제 생성 + 내 영작 테스트 — 지금 화면에 이미 있는 기능을 실제로 동작시키는 것까지
  3. 2차: 회원(로그인) + 모임 · 모임원 · 회차(events) · 출석
  4. 3차 (POC): 내가 만든 지문·문제를 같은 모임의 모임원에게 공유 — 외부 공유는 하지 않음
  5. 4차: 웹 배포 (Vercel + 클라우드 Supabase)
  6. MVP 2차 (MVP 1차 이후): 앱인토스 배포 — MVP 1차 범위 밖. 다만 정적 번들·토스 로그인 제약 대비 3가지는 2차 설계에서 비용 0으로 지켜 두길 권장
  7. Nest 분리 시점은 날짜가 아니라 트리거 조건이 충족될 때
MVP 1차 = 1~4차 (웹 배포까지) · MVP 2차 = 앱인토스 배포 — 앱인토스는 MVP 1차 범위에서 제외한다. 결제·푸시 알림·관리자 화면 등도 MVP 이후. 아래 "N차"는 MVP 1차 안의 개발 단계 번호다. 외부 공유는 회원·모임 관리(2차) 완성 이후에만, 그것도 모임 안에서만 한다.
1차 범위 = 1인 사용 (회원관리 없음)
  • 한다 ① DB·백엔드: 로컬 Supabase, 진도·답안 서버 저장(기기 간 이어하기), 생성된 지문 저장
  • 한다 ② AI: 영작 확인(CheckService), 질문 더 만들기(QuestionService), 새 지문 + 지문 딸린 문제 일체 생성(Passage 전체: 본문·번역·vocab·talk·expressions·practice·write)
  • 한다 ③ 단어 뜻 조회: 지문의 아무 단어나 누르면 뜻 토스트 — [[단어]] 표시 단어는 기존 vocab, 그 외는 GCP Cloud Translation(en→ko) + word_cache 캐시
  • 범위 한정: 새 화면은 "지문 만들기" 진입점(홈) 1개만. 나머지 6단계 화면은 기존 것을 실데이터로 연결. library-tools("준비 중")는 생성기로 채울 수 있다
  • 안 한다: 로그인, 프로필, 모임/모임원, RLS 사용자별 정책, 카카오 OAuth, 게스트 병합
  • 사용자 식별: 없음. 데이터 소유자는 고정값 'me' 한 명. 모든 DB 접근은 서버(Route Handler, service role)만 — 브라우저는 DB 키를 갖지 않는다
  • 2차 전환 비용: owner text → user_id uuid 컬럼 교체 + 기존 'me' 데이터를 내 계정으로 귀속하는 UPDATE 1회
  • 주의: 배포하면 URL을 아는 누구나 호출 가능 → AI 비용 노출. 리스크의 접근 보호 참조

01 · AS-IS현재 상태와 백엔드가 풀어야 할 것

코드에서 확인한 사실 기준.

연결 지점이 이미 있다
shared/api/services.ts 의 CheckService(영작 확인)·QuestionService(질문 더 만들기)가 인터페이스 + 목업. 구현만 교체하면 된다 → Nest 이전 때도 이 경계가 그대로 이음새.
상태는 전부 브라우저 안
entities/session reducer가 sessionStorage 에 저장. 탭 닫으면 소실, 기기 간 이어하기 불가, 모임장이 모임원 진도를 볼 수 없다.
콘텐츠는 코드에 있다
지문은 passages.ts (TS 상수). 2개(dad-video-call 사용 가능, library-tools 준비 중). Passage 한 객체가 본문·번역·vocab·talk·expressions·practice·write·pool(질문 더 만들기용 목업 후보)을 모두 품는다. 새 지문을 만드는 경로가 없다.

02 · 파괴적 제안계획에 무리가 있는 부분

요청하신 대로 돌려 말하지 않았다. 각 항목은 "채택 권장 / 선택 / 보류" 판정 포함.

채택 권장① "Next 임시 서버 → Nest 이전" 프레임을 버리고 "순수 TS 서버 모듈"로 설계

문제"임시"로 짠 Route Handler는 req/res·Next 헬퍼에 엉겨 붙어 결국 재작성이 된다. 반대로 Nest를 Vercel에 올리는 건 가능하지만 서버리스 어댑터·콜드스타트를 감수해야 하고, 무료 Nest 호스팅은 대부분 슬립(예: Render 무료)이거나 VM 직접 관리(Oracle Always Free)다.
제안비즈니스 로직은 src/server/<도메인>/service.ts 에 (Next·Nest import 금지, 입력/출력은 순수 객체). app/api/**/route.ts 는 "인증 확인 + 파싱 + service 호출"만. 이전 시 service를 Nest @Injectable 로 복사하고 route를 controller로 바꾸면 끝.
효과Nest 이전 비용이 "재작성"에서 "기계적 변환"으로 떨어진다. 지금은 서버 1개(Vercel)만 운영.

채택 권장② 서버 코드를 "덜" 쓴다 — 로그인 도입 후 단순 CRUD는 RLS로 직결 2차~

1차로그인이 없으니 RLS로 "내 것만"을 판정할 수 없다 → RLS는 켜되 정책은 만들지 않고(브라우저 직접 접근 전면 차단), 진도 저장·AI 모두 Route Handler가 service role로 접근. 서버 코드는 얇은 CRUD 몇 개뿐.
2차~진도·프로필처럼 "내 데이터만 읽고 쓴다"인 것은 supabase-js 브라우저 직결 + RLS로 전환. Next 서버는 AI 호출 · 모임 권한 로직만 맡는다.
대가RLS 정책(SQL)은 Nest로 가도 DB에 그대로 남지만, 그때 "정책 vs 서비스 레이어" 이중 구조가 된다. → 모임·모임원은 복잡한 권한 때문에 서버 서비스로 구현(RLS는 마지막 방어선으로만).

채택 권장③ 지문은 "정규화 테이블 6개"가 아니라 passages 1행(jsonb)로 저장

수정 사유AI가 지문을 생성하게 되면서 "지문은 repo에만" 안은 폐기. 생성물은 DB에 저장해야 한다.
제안passages(id, data jsonb, source 'seed'|'ai', created_at). data = 기존 Passage 객체 그대로. 기존 dad-video-call은 repo(seed) 유지 + 앱이 DB 지문과 합쳐서 목록화. 편집 UI·정규화·마이그레이션 비용 0.
핵심LLM 출력은 반드시 zod로 검증한 뒤 저장 — 형식 + 규칙(본문의 [[단어]] 전부가 vocab 키에 존재, **굵게** 짝 맞음, id 중복 없음, 문단 수 en = ko). 실패하면 1회 재시도 후 오류 표시. 검증이 이 기능의 품질 전부다.
부수 변경Passage.pool(질문 더 만들기 후보 목업)은 실제 생성으로 대체되므로 삭제.

채택 권장④ 1차는 로그인 없는 1인용, 2차는 로그인 필수 — 게스트 병합은 만들지 않는다

제안1차는 소유자 고정값 'me' 한 명으로 단순화(사용자 확정). 2차에서 로그인을 넣을 때 "게스트 → 로그인 병합"(가장 버그 많은 구간)을 만들지 말고 로그인 필수로 전환하며 기존 'me' 데이터를 내 계정에 귀속시킨다. sessionStorage는 새로고침 복구용 캐시로만 남기고 서버가 원본.

결정 필요⑤ Vercel Hobby는 "비상업적 개인 사용" 한정

문제모임 회비·유료 구독·광고 등 수익이 붙는 순간 Hobby 약관 위반 소지(Pro 월 $20/인). "추후 모임 관리까지"의 최종 모습이 수익형이면 처음부터 영향.
제안무료로 계속 가려면 Cloudflare Pages/Workers(상업 이용 허용)로 갈아타는 안이 있으나 Next 16 호환(OpenNext 어댑터)에 마찰이 있다. → 수익화 계획 유무를 먼저 정하고, 없으면 Vercel 유지, 있으면 Pro 전환 비용을 예산에 넣는다.

권장⑥ 진짜 비용은 호스팅이 아니라 AI 호출

비용 순서지문 1개 생성(긴 출력, 1~수만 토큰) > 질문 생성 > 영작 확인(짧음). 생성은 사용자가 버튼을 눌렀을 때만(자동·선생성 금지).
제안① 영작 확인: 규칙(FIXES)에 걸리면 즉시 반환, 아니면 캐시 → LLM ② (hint, answer 해시) → 결과 캐시 ③ 전역 일일 호출 상한(ai_usage) — 1차는 1인이라 사용자별이 아니라 하루 N회 ④ LLM 호출은 server/llm.ts 한 함수(llm(prompt, zodSchema))로만 → 모델·공급자 교체가 1파일. 키는 서버 env에만. 무료 티어는 약관상 입력 학습 사용 여부 확인.
